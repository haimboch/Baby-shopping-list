# Baby Smart List v0.52 — מבצעים אמינים, 3 הצעות וחיסכון מדויק

גרסה 0.52 מתקנת את מבצע הכמות השגוי שהופיע בצילום המסך ומחזקת את
המנגנון עבור כל מוצרי התינוקות וכל שבע הרשתות הפעילות במאגר.

## התקלה שנמצאה

בשורת יוחננוף של נוטרילון שלב 3, ברקוד `8712400802536`, המקור הכיל:

```text
מחיר רגיל: 63.90 ₪
כמות מבצע מובנית: 2
ערך מבצע מקורי: 110 ₪
תיאור הגבלה: נוטרילון 800 גרם עד 4 יח מעל 75
```

המפרש הישן זיהה בטעות את האות `ל` שבתוך המילה `מעל`, ופיצל את המספר
`75` ל־`7` ו־`5`. בהמשך הוא שילב את התוצאה עם הכמות המובנית `2`, ולכן
הוצג מבצע לא הגיוני של `2 ב־5 ₪`.

התוצאה הנכונה היא:

```text
2 ב־110.00 ₪
55.00 ₪ לאריזה
חיסכון בקניית 2: 17.80 ₪
```

## ארבעת השינויים המרכזיים

### 1. שלוש האפשרויות הזולות תחילה

- ההשוואה מדרגת קודם מחירים טריים וכשירים בתוך הרדיוס שהמשתמש הגדיר.
- מוצגות תחילה 3 האפשרויות הזולות ביותר.
- אם קיימות הצעות נוספות מופיע כפתור `הצג אפשרויות נוספות`.
- לחיצה נוספת על `הצג רק 3 אפשרויות` מחזירה לתצוגה המקוצרת.
- מחיר ישן מדי עדיין יכול להופיע בשקיפות, אך אינו מקבל גביע ואינו עוקף
  מחיר טרי בדירוג.

### 2. אימות קשיח של מבצעי כמות

כל מבצע עובר כעת אותה בדיקה ב־Python לפני השמירה וב־JavaScript לפני
ההצגה:

- הכמות חייבת להיות מספר שלם וחיובי.
- מחיר המבצע הכולל חייב להתאים למחיר הממוצע כפול הכמות.
- המחיר הכולל של מבצע כמות אינו יכול להיות נמוך ממחירה הרגיל של אריזה
  אחת. כלל זה עדיין מאפשר `1+1 חינם`, שבו הסכום שווה למחיר אריזה אחת.
- המבצע חייב להעניק חיסכון אמיתי לעומת קניית אותה כמות במחיר הרגיל.
- תיאור חופשי אינו רשאי לדרוס שדות מובנים כאשר הכמויות אינן תואמות.
- אם תיאור פגום יצר ערך בלתי אפשרי, המנוע מנסה שוב את הערך המובנה
  המקורי של הרשת. כך `2 ב־5` משוחזר ל־`2 ב־110` במקרה שנבדק.
- אם אי אפשר להוכיח שהמבצע תקין, הוא נפסל ומוצג המחיר הרגיל בלבד.

ההגנה בצד האפליקציה פוסלת גם שורה שגויה שכבר קיימת במסד הנתונים, עוד
לפני שריצת העדכון הבאה מתקנת אותה.

### 3. עדכון אוטומטי מסביב לשעון

- `Update Baby Prices` בודק את קובצי המחירים והמבצעים של רמי לוי,
  יוחננוף, שופרסל, Be ואושר עד בכל שעה, 24 שעות ביממה.
- `Update KSP and Super-Pharm` מתוזמן בכל שעה. מחזור הספק המלא שלו מבוצע
  אחת לארבע שעות כדי להישאר מתחת למכסה החינמית של 100 בקשות ביום.
- ריצת הסופרמרקטים השעתית משתמשת בקובצי השקיפות הרשמיים ואינה צורכת את
  מכסת CheaperSal.
- לפני כל ייבוא GitHub Actions מריץ את בדיקות Python ואת בדיקת הדפדפן.
  אם בדיקה נכשלת, הייבוא נעצר ולא נשמר מידע חשוד.

GitHub עשוי לעכב לעיתים ריצה מתוזמנת בכמה דקות; העדכון הוא אוטומטי
ורציף, אך אינו שירות זמן־אמת.

### 4. חיסכון לפי כל חבילת המבצע

כאשר המשתמש בוחר לנצל מבצע כמות, המערכת שומרת:

- מספר אריזות שנקנו בפועל.
- הסכום הכולל ששולם.
- המחיר הממוצע לאריזה.
- המחיר הרגיל ששימש להשוואה.
- החיסכון המדויק של כל הכמות.

בדוגמת `2 ב־110`:

```text
מחיר רגיל לשתי אריזות: 63.90 × 2 = 127.80 ₪
סכום המבצע:                         110.00 ₪
חיסכון:                              17.80 ₪
```

המלאי גדל ב־2, אירוע הרכישה נשמר עם `package_count = 2`, והחיסכון
מתווסף לחיסכון החודשי.

## תחולה

המנגנון אינו מקודד ליוחננוף או לנוטרילון בלבד. הוא מופעל על כל סוגי
המוצרים הקיימים באפליקציה ובכל הרשתות:

- רמי לוי
- יוחננוף
- שופרסל
- Be
- אושר עד
- סופר־פארם
- KSP

כללי הבטיחות הקיימים נשמרו: תמ״ל מושווה לפי המוצר והיצרן המדויקים,
מחירי אונליין מסומנים בבירור, ומחיר ישן מדי אינו זוכה אוטומטית.

## מסד נתונים ו־Secrets

אין צורך ב־SQL חדש, בטבלה חדשה או ב־Secret חדש. העמודות הקיימות כבר
מספיקות:

- `promo_price` — המחיר הממוצע לאריזה במבצע.
- `promo_min_quantity` — כמות המינימום.
- `promo_total_price` — הסכום הכולל לכמות המינימום.
- `calculated_savings` — החיסכון שנרשם ברכישה.

## בדיקות

- 62 פונקציות בדיקה ב־Python עברו בהצלחה.
- בדיקת JavaScript מלאה עברה בהצלחה.
- נבדקה התקלה החיה של יוחננוף גם עם הערך השגוי וגם עם הערך המקורי 110.

- נבדקו `2 ב־110`, `2 ב־25`, `3 ב־80` ו־`1+1 חינם`.
- נבדקו 3 הצעות ראשונות, הצגת כל היתר וחישוב חיסכון מדויק.
